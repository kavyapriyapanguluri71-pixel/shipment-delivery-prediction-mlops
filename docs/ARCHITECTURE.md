# Architecture

The project keeps the exploratory notebook and research paper, while providing
a separate reproducible training and serving path:

1. `Train.csv` is schema-checked by `mlops_pipeline.validation`.
2. The stratified split is made before fitting any transformations.
3. Each candidate is a scikit-learn `Pipeline` containing imputation,
   numeric scaling, categorical one-hot encoding, and its classifier.
4. Five-fold stratified cross-validation selects the candidate by mean ROC-AUC
   using only the training partition. A bounded grid search tunes that
   candidate, then the held-out test partition is evaluated once.
5. The fitted pipeline and metadata are written to `models/`; metrics,
   comparison data, feature importance, and plots are written to `outputs/`.
6. FastAPI loads the complete fitted pipeline and exposes health and
   prediction endpoints. Prediction logs omit feature values.
7. Optional monitoring compares incoming CSV feature distributions with a
   reference batch, and Kubernetes manifests run the API behind a ClusterIP
   service with health probes.

The positive class is 1 (late shipment). No identifier is used as a model
feature. Class weighting is used for estimators that support it; SMOTE is not
used, avoiding the earlier notebook issue where resampled data was computed
but not used by the training loop.

The notebook's separate pickle files under `outputs/` remain for compatibility
with its cells. They are not loaded by the API; the canonical serving artifact
is `models/shipments_pipeline.joblib`.

The model artifact uses Python pickle serialization through joblib. Load only
artifacts generated by this project or another trusted source.
